# API connection diagnosis and validation

Compared current NEXUS main (6f9edb0) with JARVIS-ULTRA-V67 provider vault and unified core. JARVIS uses a local FreeLLMAPI base at port 3847 and sends `auto`; NEXUS defaults include ports 31415 and 3847. JARVIS code was read as reference only; no dependency or source copied.

Confirmed code defects:
- Settings tested only saved configuration, ignoring newly pasted keys and edits. Connect now saves that provider securely, enables it, and discovers models with GET /models. Blank key preserves the existing OS vault entry.
- Base URLs were concatenated literally. A host-only Groq URL, /v1 URL, or pasted /chat/completions URL produced an incorrect request path. Known provider hosts are normalized to canonical API bases; custom endpoints retain their host/path.
- AUTO fallback existed on latest main, but an explicit retired model restricted a provider to one candidate. On failure, discovery now supplies bounded alternate candidates while preserving approval checks, cooldowns and the router deadline.
- FreeLLMAPI discovery now tries the other known local port after connection failure or HTTP 404. Credentials are never redirected to a different host.

The FreeLLMAPI approval message is generated by a saved paid=true flag, before any inference request. Default FreeLLMAPI configurations are paid=false. The fix does not silently erase an explicit cost designation. Only mark an endpoint free when its upstream billing is known; paid endpoints still require per-request chat approval. Groq default remains paid=true because a key alone does not establish a free billing tier.

Actual user saved keys/configuration and live service responses were unavailable. Thus the reported Groq 404 cannot be attributed conclusively to a particular saved URL versus retired model; both reproducible failure paths are covered.

Validation:
- 23 targeted router, Connect HTTP integration, secure-key preservation, paid guard, cooldown, fallback, and SQLite/file tests passed.
- Python compileall and JavaScript syntax check passed.
- Broader voice regression run: 29 passed; one failed because speech_recognition is absent; four HTTP fixture tests deselected.
- Full core suite attempted; existing synchronous Starlette TestClient fixture stalled at startup in this environment and was terminated. Async ASGI HTTP Connect integration passed.
- Live service verification and dependency installation unavailable: configured network proxy could not be reached. Windows GUI/microphone and actual 4GB-device memory measurements were not performed.

No dependencies, database schema, voice implementation, GUI layout, or credential namespace changed. Discovery remains cached and bounded; no local model is loaded by this fix. Existing deployment/user data files were not modified.
